automation-hub — Agent AI 운영 환경의 누적 메타 자산
slot · agent-friendly-env 2026 (live) proprietary, kept private by design
context
다년간 누적해온 Claude Code Agent AI 운영 자산을 single source of truth로 통합한 메타 자산. 글로벌 지침 · 에이전트 · 스킬 · 커맨드 · 템플릿 · 자동화 스크립트 · 정책을 단일 git 레포에서 관리하며, post-commit hook이 모든 PC · 프로젝트로 자동 배포. 정적 1회성 보강이 아닌 SemVer + MIGRATION + 9-field frontmatter 기반의 살아있는 시스템(Evolving System) 패러다임을 실증.
// access policy · 자산의 가치와 누적성을 보호하기 위해 의도적으로 접근 통제 운영 중이며, 진지한 채용 검토나 협업 engagement에 한해 선별적 접근을 허용합니다.
problem
1인 운영자가 다중 프로젝트에서 Claude Code Agent 환경을 운영할 때 (1) 자산 드리프트 — 글로벌 지침 변경이 N 프로젝트에 자동 전파되지 않으면 일관성 깨짐. (2) 정적 자산 한계 — 1회 작성한 스킬 · 에이전트가 진화하지 않으면 새 패러다임(Agent AI 시대)에 뒤처짐. (3) 메타 시각 부재 — 다중 프로젝트의 비전 · 로드맵 · 유기적 연계가 한 문서로 통합되지 않으면 cross-project 의사결정이 어려움. (4) 자산 보호 — 누적된 운영 자산이 무분별하게 노출되면 그 자체의 차별 가치를 잃음.
approach
  • A. Git SSOT + 자동 배포 — automation-hub/global/을 single source of truth로, post-commit hook이 모든 PC의 ~/.claude/에 자동 sync
  • B. project-curator 에이전트 + 4 도구 — setup-new-project / drift-check / migrate / version 인터페이스 정의
  • C. Evolving Template Architecture (ADR-002) — 모든 자산에 SemVer · MIGRATION · 9 필드 frontmatter 의무 적용
  • D. master-ecosystem-overview — 활성 생태계 다중 프로젝트의 다층 정체성 8축 + 유기적 연계 4 관점 매트릭스 + Phase 진화 로드맵을 단일 문서로 정의
  • E. PC별 어시스턴트 정체성 운영 — ops1=제니퍼, ops2=Nova처럼 PC별로 어시스턴트 이름을 분리해 멀티 PC 컨텍스트를 명확히
  • F. 자체 자산 진화 사례 누적 — 본 cycle만 해도 master-ecosystem v0.2 → v1.0 major 갱신을 PR 머지로 영구 기록
  • G. 접근 통제 정책 — 자산의 차별 가치를 보호하기 위한 의도적 비공개 운영. 진지한 engagement(채용 검토 · 전략 협업)에 한해 선별적 invite 가능
result
1인 단독 기획 · 설계 · 구현 · 운영. 살아있는 자산이 정적 자기소개보다 강력하다는 사실을 자기 자신으로 증명 — 자산의 진화는 내부 git log로 영속 기록되며, 진지한 검토 단계에서 선별 공유 가능. 본 포트폴리오 사이트 또한 automation-hub의 다음 사용 사례로 진화 중 — 사이트 자체가 비공개 자산의 첫 공개 산출물이라는 메타 구조.

problem
(1) 대용량 스포츠 원본 영상을 서비스 가능한 스트리밍 포맷으로 안정적으로 변환 + AI 분석 기반 데이터 생성. (2) 선수 · 팀 · 학교 · 종목 · 리그 · 이벤트 메타데이터를 일관된 스키마로 통합 관리. (3) STT · OCR · 이벤트/액션 분석 · 하이라이트 추출 AI 파이프라인을 비동기로 안정 운영. (4) GPU 메모리 · Worker 재시작 · 대용량 디스크 · Queue 장애 · NAS 마운트 등 다영역 운영 이슈 동시 관리.
approach
  • A. 인코딩 서비스 직접 설계 · 구현 · 배포 — MP4 표준본이 아닌 TS 기반 운영(.m3u8 + .ts), 서비스 스트리밍 최적화 중심. 대용량 영상 처리 안정성을 우선한 의도적 의사결정
  • B. 클립/하이라이트 생성 — 원본 영상 기준 시간 정보로 지정 구간 추출, TS/MP4 생성 후 HLS 재생용 변환
  • C. 하이라이트 병합 — MP4 병합 후 최종 HLS 변환 패턴으로 재인코딩 최소화 (운영 + 안정성 우선 트레이드오프)
  • D. AI 연계 파이프라인 — FastAPI + Redis Queue + RQ Worker + GPU 분석 서버 + Docker 운영. 동기 · 비동기 경계 명확화
  • E. 운영 인프라 분리 — 인코딩 · AI(GPU) · NAS · 운영 웹 · Redis 서버 분리 + 방화벽 기반 DMZ/내부망/SSL VPN 다층 보안
  • F. 메타데이터 DB 설계 · 구현 — 선수 · 팀 · 학교 · 종목 · 리그 · 이벤트 통합 스키마, 추후 AI 분석 결과 연결성 우선

problem
(1) 1인이 기획부터 유지보수까지 8단계 전 과정을 단독 수행하면서도 운영 안정성과 시스템 정합성을 유지해야 함. (2) AMR 물류로봇 · 통합관제 · 공정관리 · 작업관리 · 생산관리 다영역 자동화를 단일 솔루션으로 통합. (3) Edge IoT 센서 · 액추에이터 · 외부 PLC · 로봇 시스템 간의 실시간 데이터 흐름 안정화. (4) 현장 환경 변수(전원 · 네트워크 · 물리 제약)와 솔루션 아키텍처의 정합성 유지. (5) 회사 비공개 원칙 하에서도 솔루션화 가능한 추상 계층 설계.
approach
  • A. 풀스택 단독 아키텍처 — .NET 10 + Clean Architecture (Domain / Application / Infrastructure / Web API / MudBlazor + Blazor Server / Edge IoT) 6 레이어를 1인이 일관되게 끌고 가는 base
  • B. 4축 통합관제 — 통합관제 · 공정관리 · 작업관리 · 생산관리 도메인을 단일 솔루션 내에서 정합성 유지하며 통합
  • C. AMR 물류로봇 연계 — 외부 로봇 시스템과의 API/프로토콜 통합으로 물류·공정 흐름 자동화
  • D. Edge IoT 실시간 파이프라인 — 센서 · 액추에이터 · PLC 간 gRPC 기반 통신, 시계열 DB 영속화
  • E. Agent AI 운영 환경 연계 — 별도 카드로 소개한 통합 Agent AI 운영 환경을 본 솔루션 개발 · 운영에 직접 적용해 1인 부담을 자동화로 분산
  • F. 현장 배포 표준화 — 다중 사이트 배포 가능한 구조로 설계, 솔루션화 지향
