context
자율 AI 에이전트들이 한 프로젝트의 SW 라이프사이클 전체를 협업 수행하도록 직접 설계·구축 중인 멀티에이전트 오케스트레이션 프레임워크. 오케스트레이터(chair) 1기 + 8개 도메인 마스터 에이전트가 거버넌스된 상호-비신뢰 peer로 협업한다. 핵심은 "단순 LLM 호출"이 아니라 에이전트들을 어떻게 깨우고·인증하고·통신·기억시킬지를 1급 아키텍처로 다루는 에이전트 경험(AX) 설계. 이 환경 자체가 다수 프로젝트를 병행 운영하기 위한 본인의 핵심 운영 인프라다.
A multi-agent orchestration framework I'm designing and building so that autonomous AI agents collaborate across a project's entire software lifecycle. One orchestrator (chair) + 8 domain master agents work as governed, mutually-untrusted peers. The discipline is not "calling an LLM" but agent-experience (AX) design — treating how agents wake, are authorized, communicate, and remember as first-class architecture. This environment is my core operational infrastructure for running multiple projects in parallel.
problem
(1) 자율 LLM 에이전트 다수를 안전하게 협업시키는 거버넌스 부재 — 권한 · 신원 · 루프 · 감사. (2) 에이전트 간 통신을 신뢰 경계 위에서 설계 (발언권 ≠ 실행권). (3) 작업 분배 · 소유권 race — claim · lease · 중복 실행 방지. (4) 세션을 넘는 기억 영속 · 검색. (5) 1인이 다중 도메인 풀스택을 끌면서 추적성 · SSOT · 회귀 baseline을 동시 유지.
(1) No governance to make many autonomous LLM agents collaborate safely — permissions · identity · loops · audit. (2) Designing inter-agent communication on a trust boundary (speech-right ≠ execution-right). (3) Work distribution · ownership races — claim · lease · double-run prevention. (4) Memory persistence · search across sessions. (5) A single operator driving multi-domain full-stack while preserving traceability · SSOT · regression baselines.
approach — 7 patterns
위협모델 기반의 문서화된 설계 결정 34건 위에 설계한 핵심 7 패턴:
7 core patterns, built on 34 documented design decisions (threat-model-based):
  • A. Deny-by-default 권한 매트릭스 + append-only 감사 — 3 거버넌스 티어 · 리스크 클래스 R0–R3 · TTL grant, 거부(deny)도 보안 신호로 영구 기록
  • B. Taint-intersection 권한 — 트리거 체인 전체의 권한 교집합으로 confused-deputy(권한 세탁) 차단, taint 리셋은 인간만
  • C. 상호-비신뢰 에이전트 모델 — 서버측 신원 확정(클라이언트 주장 무시 · token 검증) · 발언권 ≠ 실행권 · 무방향 참가자집합 루프 가드
  • D. MCP "전령(herald)" — LLM-free 씬 게이트웨이, 11개 도구로 에이전트가 실제 백엔드에 작업 push/pull · 요청마다 토큰 재로딩(무중단 회전)
  • E. 하이브리드 워커 오케스트레이션 — 작업 큐 SSOT · CAS claim · lease-TTL(idempotent 갱신) · fencing token(stale 워커 덮어쓰기 차단) · 만료 sweeper
  • F. File-SSOT + 재생성 가능한 파생 인덱스 메모리 — 로컬 마크다운 = 권위 SSOT, 검색 인덱스는 파일에서 재생성 가능한 파생물(단방향 file→DB로 drift 제거). 인덱스 구현은 벡터 임베딩 → 비-RAG 렉시컬·그래프 방향으로 재설계 진행 중
  • G. 유휴-실패 통합 신뢰성 계층 — credential keep-warm · SSE 재인증 · monotonic seq 커서 catch-up(at-least-once 전달)
  • A. Deny-by-default permission matrix + append-only audit — 3 governance tiers · risk classes R0–R3 · TTL grants; denials are permanently logged as a security signal too
  • B. Taint-intersection authority — effective permission = the intersection across the whole trigger chain, blocking confused-deputy privilege laundering; only a human resets taint
  • C. Mutually-untrusted agent model — server-determined identity (ignore client-claimed sender · verify token) · speech-right ≠ execution-right · undirected participant-set loop guard
  • D. MCP "herald" — an LLM-free thin gateway; 11 tools let agents push/pull work into a real backend · per-request token reload (zero-downtime rotation)
  • E. Hybrid worker orchestration — task queue as SSOT · CAS claim · lease-TTL (idempotent renew) · fencing token (stale worker can't overwrite) · expiry sweeper
  • F. File-SSOT + regenerable derived-index memory — local markdown = authoritative SSOT; the search index is a regenerable derivative of the files (one-way file→DB eliminates drift). Index implementation is being redesigned from vector embeddings toward a non-RAG lexical + link-graph approach
  • G. Unified idle-failure reliability layer — credential keep-warm · SSE re-auth · monotonic seq-cursor catch-up (at-least-once delivery)
